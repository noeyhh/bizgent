# CLAUDE.md

이 파일은 이 저장소에서 작업하는 AI 코딩 도구가 먼저 읽는 작업 기준입니다.

## 1. 프로젝트 개요
- 프로젝트명: BizGent (소상공인을 위한 AI 디지털 마케팅 에이전트)
- 수업: 정보시스템 프로젝트 캡스톤 디자인 / 팀: 사계절
- 팀원: 정지민(팀장·PM), 엄지훈(Backend·DB·AI API 연동), 황아현(Frontend·UI)
- 기준 문서: `01_기획/PROJECT.md` — 기능 목록(F01~F19), 개발 범위, 무료/구독 정책의 기준

## 2. 기술 스택 (확정)
- Backend: Java, Spring Boot (MVC: Controller → Service → DAO)
- View: Thymeleaf 템플릿 + HTML, CSS, JavaScript
- Database: Oracle
- AI: LLM API(기획·문구), 이미지 생성 API(광고·대표 이미지) — 개발 중에는 목업 사용 가능
- 화면 디자인 기준: Figma Make 프로토타입(React 코드)을 **참고만** 하고, 실제 구현은 Thymeleaf로 옮긴다.
- CSS 방식(Tailwind 사용 여부, 사용한다면 CDN/빌드 방식)은 팀 확인 후 확정 — 확정 전에는 임의로 정하지 말고 먼저 물어볼 것.

## 3. 폴더 구조
- `01_기획/` — PROJECT.md 등 기획 문서 (수정 금지)
- `02_요구사항분석/` — 유스케이스 (수정 금지)
- `03_화면설계/` — 화면설계서 (수정 금지)
- `04_DB설계/` — ERD (수정 금지)
- `05_프로토타입/` — Figma Make에서 내려받은 React 코드. **디자인·동작 참고용, 수정 금지**
- Spring Boot 프로젝트 위치는 팀 확인 후 정한다 (만들기 전에 위치를 먼저 물어볼 것).

## 4. 반드시 지킬 규칙
1. `01_기획/PROJECT.md`를 포함한 문서 폴더(01~04)의 파일은 사용자가 요청할 때만 수정한다.
2. `05_프로토타입/`은 읽기만 한다.
3. PROJECT.md의 필수 기능과 핵심 흐름(매장 등록 → 목표 설정 → AI 기획 → 콘텐츠·이미지 설정 → 시안 비교 → 게시 → 매출 입력 → 성과 분석 → 개선 방향)을 빠뜨리지 않는다.
4. 기능을 추가·삭제·변경하게 되면 작업 전에 사용자에게 알리고, PROJECT.md·유스케이스·ERD 중 어디에 영향이 있는지 함께 말한다.
5. 큰 작업은 한 번에 하지 않는다. 화면 1개(또는 기능 1개) 단위로 계획을 먼저 설명하고 진행한다.
6. 확인되지 않은 내용은 추측하지 않는다. 모르면 묻는다.
7. 답변은 한국어 존댓말로 하고, 사용자를 "아현님"으로 부른다. 결론을 먼저 말하고 설명은 짧게 한다.
8. 커밋·푸시는 사용자가 요청할 때만 한다. main 브랜치에 직접 커밋하지 않는다.
9. API 키, DB 비밀번호 등 비밀정보는 코드에 직접 쓰지 않고 `.gitignore` 대상 설정 파일로 분리한다.
